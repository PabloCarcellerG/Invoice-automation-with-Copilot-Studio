1. Choose the outcome, not a fixed process

Start with the agent + Capture and check. Measure manual minutes per invoice. Main cost driver: documents requiring extraction and correction.

Keep the customer's working processes. An approval-only solution can use invoices already captured elsewhere; it does not need a new intake workflow. A visibility-only assistant needs no write workflow.

2. One Copilot Studio solution

The agent understands requests, explains blockers and finds the next action. Workflows carry out the selected business steps using authorized tools. All orchestration stays in Copilot Studio; connected tools supply records, documents and finance actions.

Connected tools: AI Builder for extraction, or optional Azure Document Intelligence; SharePoint for documents, or optional Azure Blob Storage. Dataverse retains invoice status and decisions. Azure is a potential cost option, not a guaranteed saving or a replacement for Copilot Studio orchestration.

Customer finance: choose a Dynamics 365, SAP or other ERP adapter. Reuse the same workflow contract; configure the customer's supported API/connector, permissions and reliable submission-status lookup.

3. Pick the workflow building blocks

Capture and check

Read invoice fields, check required data and duplicates, then create a ready invoice or a review task.

Value: less rekeying.
Use when: intake is the bottleneck.

Resolve and approve

Explain a blocker, route to the right person and record the authorized decision against the current invoice version.

Value: less chasing.
Use when: approvals cause delays.

Register and track

Send an approved invoice through the finance tool and confirm the result. Check an unknown result before repeating a submission.

Value: less hand-off effort.
Use when: registration is still manual.

Always keep: customer-specific access, duplicate protection for submissions and valid approval for financial writes. The agent never executes payments or changes supplier bank details.

Human in the loop, at any stage. Uncertain fields, unusual amounts, mismatches, duplicate/fraud flags or unsupported cases pause the affected automation. An assigned person corrects, rejects or escalates. Resume only after revalidation; material changes need approval again. Overdue cases escalate, never auto-approve. An unknown ERP result must be reconciled before another submission.

More requirements? Extend a step, not the whole solution.

The reusable core exposes extension points for intake, extraction, validation, approval, finance and archiving. Add a PO check, country rule or extra approval level as a versioned module; swap an ERP or extraction adapter without redesigning the three workflows. Each customer pack selects modules, rules, reviewers and budget. New modules still need implementation and dependency checks.

Illustrative EUR assumptions, not product pricing or guaranteed cash savings. Include all licenses, credits, tools, storage and support in monthly cost. Include human review in target handling minutes; do not count it twice.

Adjust the assumptions to the customer's baseline and quote.
